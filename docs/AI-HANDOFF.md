## 4. How a question is made (the core idea)
Each skill has `gen:{1,2,3}` (tier 1 guided, 2 practice, 3 challenge). A generator returns ONE question built with `mcq / mcqNum / mcq2 / numeric / shade / setclock / order`. The core validates every question:
1. `truth` is recomputed independently of `correct`.
2. Pictures are **decoded** (the auditor reads the answer back out of the SVG geometry).
3. Correct answer present exactly once; no distractor can also be right.
4. Distractors are misconceptions first, filler last; each wrong option has a `why` shown to the child and the parent.
5. Every explanation states the answer; every question has a hint that does not give it away.
Question object: `{type, prompt, visual, hint, explain(html with .eh/.step), options[{key,label,why}], correct, correctKey, truthKey}`. For `numeric` the feedback comes from `q.wrongWhy('n:<value>')`.
Text helpers to keep grammar right: `plural(n,one,many)`, `nnoun(n,'pencils')` ("1 pencil"/"3 pencils"), `isAre(n)`, `singular`, `stripTags`.
Full rules and builders: **docs/SPEC.md**.

### Add a new skill
1. Read `docs/SPEC.md` and a reference skill (`src/skills/time-quarters.js`, `fractions-read.js`).
2. Create `src/skills/<strand>-<name>.js` (IIFE → `registerSkill`). Use a unique `order`, correct `prereq`, `year` (2 review, 3, 4 bridge).
3. Add the skill to `curriculum/curriculum.json` mapping; run `node tools/curriculum-export.js` then `node tools/curriculum-report.js`.
4. `node tools/audit.js --files <prefix> --n 2500` (loads only core/visuals/your files). Then read 10+ printed samples (prompt, options, hint, explain) yourself.
5. `node tools/build.js` then `node tools/run-all.js --full`.

## 5. Learning model (engine.js)
- **Explorer's Quest** = adaptive diagnostic (`diagStart/diagNextItem/diagRecord`); old half-done quests migrate via `migrateQuestToDiag`. +3 ⭐ per land (`LAND_STARS`), 20 ⭐ welcome gift (`WELCOME_STARS`).
- Per skill: lesson (+mini-quiz) → magic trick → guided → practice → challenge → medals bronze/silver/gold. Gold requires remembering on another day.
- Spaced repetition `REVIEW_DAYS=[0,1,2,4,7,14,30]` ("Brain boost"). Evidence log per answer (capped, `EVIDENCE_CAP`). Parent metrics keep **coverage, accuracy, fluency and mastery separate** on purpose.
- Daily **mission** of ~25 min (`MISSION_SECONDS`); two low sessions in a row → the app proposes the weakest prerequisite. Year 4 opens when ≥80 % of Year 3 skills are ≥ silver (`GATE_SILVER`).
- Economy: `PACK_COST=15` ⭐ sticker pack; infinite stickers (creature × accessory × background × rarity). Parent can multiply wardrobe prices (`shopMult` ∈ {1,2,3,5}); surprise box `BOX_COST=12`. Legendary items need gold medals.
- State: `localStorage` key `melissaMathState_v4` (v3/v2 keys migrate). `loadState/mergeState/importState/defaultState`. Backup/export/import/undo are in the parent panel (Spanish; asks a multiplication question first). Backup reminder after `BACKUP_DAYS=7`.
- **Any change to state shape needs**: migration in `mergeState`, a fixture in `tools/fixtures`, and `state-test` passing. Never lose her progress.

## 7. Build and test tooling
```
node tools/build.js                 # → index.html (+ node --check + screen/action audit)
node tools/run-all.js               # quick suite   (npm test)
node tools/run-all.js --full        # before merging (npm run test:full)
```
Suite steps: build, index (index.html equals src build), audit (every answer recomputed), engine, state, mastery, mission, diag, curric, **clarity**, **textmath**, **textlint**, grammar, e2e (real Chromium), layout (360/390/430 px), touch (Chromium only), gold, diagui, missionui, parent, avatar, wardrobe, safety.
Text scanners (added Oct 2026 after wording errors slipped through):
- `tools/clarity-scan.js` — prompts: bare placeholders, missing instruction, ambiguous wording.
- `tools/text-math-check.js` — finds arithmetic statements inside hints/explanations/feedback and recomputes them (exit 1 on any false statement). Exempt contexts are listed at the top of the file.
- `tools/text-lint.js` — grammar/format rules over ALL child-visible text (singular/plural "1 steps", a/an, empty lists "and .", leaked variables `undefined`, double punctuation…). Uses `tools/text-dump.js`.
- `tools/text-dump.js [outdir]` — writes hint/explain/why/wrong/lesson/trick `.txt` (digits→#, names→NAME) **for human reading**. Do this after any wording change and read the new lines.
- `tools/grammar-scan.js`, `tools/layout-audit.js`, `tools/touch-test.js` (simulates iOS lost-click), `tools/make-review-sheet.js` (teacher review sheet).
**NOT verified by any test**: real iPad/WebKit, offline/PWA behaviour, a child actually using the economy and prices, and whether a UK teacher agrees with the content. Do `docs/IPAD-CHECKLIST.md` on the device.

## 9. Publishing procedure (exact)
Direct pushes to `main` return 403 and GraphQL is blocked, so:
1. `node tools/run-all.js --full` must be ALL GREEN.
2. Commit on branch `matemagics-v4` and push. Commit messages end with the two attribution trailer lines the session gives you.
3. Open PR with `gh api repos/Rich-mond1/melissa-mate/pulls -f title=… -f head=matemagics-v4 -f base=main -f body=…`.
4. Merge: `gh api -X PUT repos/Rich-mond1/melissa-mate/pulls/N/merge -f merge_method=merge`.
5. Poll `https://rich-mond1.github.io/melissa-mate/index.html?cb=<timestamp>` with curl until it is byte-identical to local `index.html`.
6. Tell the user; Melissa may need to reload (close and reopen the app) on the iPad.

## 10. Known caveats and open items
- Sync between devices is built (docs/SYNC.md). Her iPad and the phone were separate profiles before it; the first sync asks the grown-up which avatar/settings to keep.
- Open wording items (not wrong answers, but clumsy for an 8-year-old) are in `docs/WORDING-BACKLOG.md`. Fix them in order of value; `tools/text-lint.js` and `tools/text-math-check.js` guard against regressions.
- iPad/WebKit, offline and PWA install are unverified by automation (touch test = Chromium only).
- Economy and prices untested with a child; pet-clothes placement only checked in Chromium screenshots.
- Curriculum: 2 known order conflicts (see `curriculum.json → knownOrderConflicts`), content not validated by a teacher.
- Visuals were audited by decoding geometry, not by a human looking at all of them.
- The wording review of Oct 2026 covered ~10 500 distinct child-visible texts (prompts, hints, explanations, option feedback, lessons, tricks, UI). It found and fixed real defects (empty lists "and .", "1 tenths", leaked variable names, a physically wrong clock lesson, false equalities in worked examples). Expect more of the same kind: re-run `text-dump.js` and READ new text after changes.
- `README.md` mentions "56 habilidades"; the real count is 72 skills.
